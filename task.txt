1. GLOBAL ARCHITECTURE & TEAM COLLABORATION RULES
================================================================================
- Branching Strategy:
  * `main`: Always protected, deployable, with 100% passing automated test suite.
  * Feature Branches:
    - Person 1: `feature/ui-clinical-redesign`
    - Person 2: `feature/perf-streaming-engine`
    - Person 3: `feature/docker-ci-cd`
  * Never push directly to `main`. Every merge must go through a Pull Request (PR)
    with code review and CI verification.

- Zero Secrets Policy:
  * Never commit `.env` or plain API keys (Deepgram, Gemini, OpenAI).
  * Always use `.env.example` as the canonical environment template.
  * Local databases (`*.db`, `*.sqlite3`) and audio uploads (`uploads/`) are
    strictly ignored by `.gitignore`.

- File Ownership Boundaries:
  * Person 1 owns: `frontend/src/**`, `frontend/index.html`, `frontend/tailwind.config.js`
  * Person 2 owns: `backend/services/**`, `backend/routers/**`, `backend/database.py`, `backend/data/**`
  * Person 3 owns: `Dockerfile*`, `docker-compose.yml`, `.github/workflows/**`, `deploy/**`, `nginx.conf`
  * Shared files (`README.md`, `requirements.txt`, `backend/models/**`) require
    cross-team sign-off before modifying schemas.

- Medical Non-Inference Commitment:
  * Never infer unspoken patient sex from names or pronouns.
  * Never infer medication durations if not explicitly dictated.
  * Never invent diagnoses from isolated symptoms.
  * Require explicit doctor confirmation for uncertain candidate matches (e.g. Pan-D).

3. PERSON 2: SENIOR BACKEND & AI PERFORMANCE ENGINEER
================================================================================
Role: Lead Backend, STT/LLM & Systems Performance Engineer
Git Branch: feature/perf-streaming-engine
File Ownership:
  - backend/services/**
  - backend/routers/**
  - backend/database.py
  - backend/data/medicines/**
  - backend/tests/**

MISSION OVERVIEW:
Elevate backend throughput, reduce end-to-end transcription latency to near zero,
and optimize the clinical extraction engine. Ensure the system scales smoothly
under concurrent doctor dictations without memory leaks, SQLite write locks, or
slow substring iterations.

DEEP TECHNICAL BRIEF:
1. Real-Time Audio Streaming via WebSockets:
   - Implement a WebSocket endpoint (`/ws/transcribe/{prescription_id}`).
   - Stream raw audio chunks directly from browser `MediaRecorder` (100ms chunks)
     to Deepgram Live Streaming API via WebSockets.
   - Emit intermediate transcripts (`is_final=False`) to the frontend in real time
     so the doctor watches words appear while speaking.
   - Finalize prescription record automatically when the WebSocket receives audio EOF.

2. Sub-Millisecond Medicine Matching & In-Memory Indexing:
   - Current status: Alias matching does regex scans over sorted terms.
   - Optimization: Implement an in-memory **Trie** or **Aho-Corasick automaton** in
     `backend/services/medicines/alias_matcher.py`.
   - Benchmark target: Match queries against 50,000+ Indian brand names and SNOMED
     CT India drug extensions in $< 0.5\text{ ms}$ per clause.
   - Expand `medicine_aliases.json` catalog with generic compositions (e.g. Paracetamol,
     Amoxicillin-Clavulanate, Metformin, Telmisartan, Pantoprazole-Domperidone).

3. Database Concurrency & SQLite WAL Mode:
   - Configure SQLite `PRAGMA journal_mode = WAL;` (Write-Ahead Logging) to eliminate
     database lock contention between concurrent reads and writes.
   - Enable `PRAGMA synchronous = NORMAL;` and `PRAGMA cache_size = -64000;` (64MB memory cache).
   - Add database indexes:
     * `CREATE INDEX IF NOT EXISTS idx_prescriptions_status_date ON prescriptions(status, updated_at DESC);`
     * `CREATE INDEX IF NOT EXISTS idx_medicine_items_rx ON medicine_items(prescription_id, item_index);`
     * `CREATE INDEX IF NOT EXISTS idx_audio_records_rx ON audio_records(prescription_id);`

4. Extraction Engine Robustness & Code-Mixing:
   - Support regional Indian English number formats (e.g., "ek goli", "do chamach",
     "teen baar", "10 din", "OD", "BD", "TDS", "HS", "SOS").
   - Handle self-corrections with lookahead:
     "Dolo 500... sorry make that Dolo 650" -> Extract only final value 650mg.
   - Strict Non-Inference: Keep patient sex `None` when unstated; do not invent duration;
     leave diagnosis empty unless explicitly dictated.

================================================================================
Role: Lead DevOps, Containerization & CI/CD Platform Engineer
Git Branch: feature/docker-ci-cd

  - Dockerfile.frontend
  - docker-compose.yml
  - docker-compose.prod.yml
  - nginx.conf

MISSION OVERVIEW:
Provide production-ready containerization, reproducible builds, and automated
continuous integration / continuous deployment (CI/CD). Ensure any engineer or
hospital IT administrator can spin up the full application with a single command,
backed by automated regression checks on every GitHub pull request.

DEEP TECHNICAL BRIEF:
1. Multi-Stage Production Dockerfiles:
   - `Dockerfile.backend`:
     * Base: `python:3.13-slim-bookworm`.
     * Multi-stage build: Stage 1 builds wheels; Stage 2 copies wheels and installs
       without gcc/build tools to minimize attack surface and image size (< 200MB).
     * Non-root user: Run as `appuser:appgroup` (UID/GID 10001).
     * System dependencies: Include `ffmpeg` for audio conversion and `curl` for healthchecks.
     * Health check: `HEALTHCHECK --interval=30s --timeout=5s CMD curl -f http://localhost:8000/docs || exit 1`.
   - `Dockerfile.frontend`:
     * Stage 1 (Builder): Node.js 22 alpine, runs `npm ci` and `npm run build`.
     * Stage 2 (Runner): `nginx:alpine-slim`.
     * Copies compiled static bundle from builder to `/usr/share/nginx/html`.
     * Hardened Nginx configuration with gzip, brotli, cache headers for assets,
       and reverse proxy `/api/` forwarding to backend container.

2. Container Orchestration (`docker-compose.yml`):
   - Service `backend`:
     * Exposed on internal network port 8000.
     * Environment variables mapped from `.env`.
     * Named persistent volumes: `voice_rx_db:/app/data`, `voice_rx_uploads:/app/uploads`,
       `voice_rx_pdf:/app/pdf_output`.
     * Resource limits: 1 CPU, 1GB RAM.
   - Service `frontend`:
     * Exposed on host port 80 (or 5173 for development).
     * Depends on `backend` with healthcheck condition `service_healthy`.
   - Service `dev` overlay: Mount local source directories for hot-reloading development.

3. GitHub Actions CI/CD Pipeline (`.github/workflows/ci.yml`):
   - Pipeline stages:
     1. **Linting & Code Quality**:
        - Backend: `ruff check backend/` and `ruff format --check backend/`.
        - Frontend: `eslint frontend/src/` and `tsc --noEmit`.
     2. **Automated Test Suite**:
        - Run `pytest backend/tests/` with coverage reports.
        - Run frontend unit/component tests (`npm test`).
        - Enforce failure if test pass rate < 100% or coverage drops below 85%.
     3. **Container Build & Verification**:
        - Build both Docker images via `docker buildx`.
        - Run `docker compose up -d` in test runner and verify healthcheck endpoint.
     4. **Automated Docker Image Release (on merge to main)**:
        - Tag with git commit SHA and `latest`.
        - Push to GitHub Container Registry (`ghcr.io/shreyabhat75/voice-prescription-writer`).

4. Production Deployment & Security:
   - Provide deployment guides for cloud providers: AWS Lightsail, DigitalOcean App Platform,
     Railway, and on-premise hospital local server.
   - Configure HTTPS/TLS with Let's Encrypt / Caddy reverse proxy template.
   - Add automated log rotation to prevent SQLite or uvicorn log bloat.
